# Creational patterns

Creational patterns deal with how objects are created. They hide the details of construction, so code depends on what it needs rather than on how that thing is built.

| Pattern | Intent | Status |
|---------|--------|--------|
| [Singleton](singleton/README.md) | Ensure a class has only one instance and provide a global point of access to it. | implemented |
| [Factory Method](factorymethod/README.md) | Define an interface for creating an object, but let subclasses decide which class to instantiate. | implemented |
| [Abstract Factory](abstractfactory/README.md) | Provide an interface for creating families of related objects without naming their concrete classes. | implemented |
| [Builder](builder/README.md) | Separate the construction of a complex object from its representation, so the same steps can build different results. | implemented |
| [Prototype](prototype/README.md) | Create new objects by copying an existing instance instead of building them from scratch. | implemented |
