# Behavioral patterns

Behavioral patterns deal with how objects communicate and how responsibilities are divided between them.

| Pattern | Intent | Status |
|---------|--------|--------|
| [Chain of Responsibility](chainofresponsibility/README.md) | Pass a request along a chain of handlers until one handles it, so the sender doesn't need to know the receiver. | implemented |
| [Command](command/README.md) | Wrap a request in an object, so requests can be queued, logged and undone. | implemented |
| [Interpreter](interpreter/README.md) | Define a grammar for a small language and an interpreter that evaluates sentences in it. | implemented |
| [Iterator](iterator/README.md) | Access the elements of a collection one by one without exposing how it is stored. | implemented |
| [Mediator](mediator/README.md) | Define an object that controls how a group of objects interact, so they don't refer to each other directly. | implemented |
| [Memento](memento/README.md) | Capture an object's internal state so it can be restored later, without breaking encapsulation. | implemented |
| [Observer](observer/README.md) | Define a one-to-many dependency so that when one object changes, all its dependents are notified. | implemented |
| [State](state/README.md) | Let an object change its behavior when its internal state changes, as if it changed its class. | implemented |
| [Strategy](strategy/README.md) | Define a family of interchangeable algorithms and let the client pick one at runtime. | implemented |
| [Template Method](templatemethod/README.md) | Define the skeleton of an algorithm once and let subclasses fill in specific steps without changing its order. | implemented |
| [Visitor](visitor/README.md) | Add new operations over a set of element types without changing those element classes. | implemented |
