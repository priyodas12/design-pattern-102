# Structural patterns

Structural patterns deal with how classes and objects are composed into larger structures, keeping those structures flexible and efficient.

| Pattern | Intent | Status |
|---------|--------|--------|
| [Adapter](adapter/README.md) | Convert the interface of a class into another interface clients expect, so incompatible classes can work together. | implemented |
| [Bridge](bridge/README.md) | Decouple an abstraction from its implementation so the two can vary independently. | implemented |
| [Composite](composite/README.md) | Compose objects into tree structures and let clients treat single objects and groups the same way. | implemented |
| [Decorator](decorator/README.md) | Attach extra responsibilities to an object dynamically, as a flexible alternative to subclassing. | implemented |
| [Facade](facade/README.md) | Provide one simplified interface to a set of interfaces in a subsystem. | implemented |
| [Flyweight](flyweight/README.md) | Share common state between many fine-grained objects so large numbers of them stay cheap. | implemented |
| [Proxy](proxy/README.md) | Provide a stand-in for another object to control access to it. | implemented |
